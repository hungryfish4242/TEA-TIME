# Local provider guide (Alibaba Cloud Model Studio)

The user explicitly supplied the endpoint, model and key and requested local configuration. The secret is stored only in ignored `.local/config.json`. Do not copy it into JavaScript, screenshots, command logs, packages or Git. On 23 October 2026 the user replaced the original DeepSeek credential with an Alibaba Cloud Model Studio (Bailian) key; the previous configuration file had already been removed locally, so nothing was migrated.

Run `uv run python server.py --port 8000`. The server binds to loopback, serves only allowlisted application assets and provides `/api/status` and `/api/guide`. Browser code never receives the key. Static offline packages retain mock answers; `?offline=1` forces that mode on the local server as well.

The configured provider base is `https://dashscope.aliyuncs.com/compatible-mode/v1`, model `qwen-flash`, using the OpenAI-compatible `/chat/completions` contract with bearer authentication, non-streaming responses and at most 450 output tokens. `server.py` accepts only HTTPS hosts in its allowlist (`api.deepseek.com` with the Anthropic `/v1/messages` contract, `dashscope.aliyuncs.com` with the OpenAI contract) and selects the contract from the config `protocol` field (`openai` or `anthropic`). Model probes on 23 October 2026: `qwen-flash` 3,266 ms cold and `qwen-plus` 1,937 ms; `qwen-turbo` returned HTTP 429 under the workspace request limit. The first real `/api/guide` answer arrived in 6,890 ms including cold start, inside the 7-second server and 8-second browser deadlines.

Requests are limited to 120 question characters, the current table's conversation, six provider requests per visit and a 7-second server timeout. The browser imposes an 8-second deadline and falls back to the current table's local bank. Host/Origin checks and JSON-only POSTs prevent foreign-site browser calls. Request bodies, credentials and provider responses are not persisted in server logs. Provider retention is governed by DeepSeek's terms; no no-training or deletion guarantee is asserted here.

The model receives only the chapter-specific development source descriptions and instructions to refuse unsupported cultural claims. Responses must have at most 90 words, a valid topic, known source IDs, safety status and no HTML. This is real model integration, but the available corpus is still interface material: it is not a completed cultural-history RAG corpus.

Initial real call succeeded in 1,063 ms with a 31-word answer and source `DEV-QA-01`. Subsequent automated grounding/contract evaluation is recorded separately; neither replaces human cultural review.

The 45-case live evaluation passed its backend checks. Final review found that 17 real responses used permitted UI source IDs initially omitted from the frontend validator; the frontend now accepts the same chapter QA/UI source union as the backend. A browser HTTP fixture explicitly covers such a UI citation. This distinction is preserved: backend evaluation is not by itself proof that the frontend displayed every result.
